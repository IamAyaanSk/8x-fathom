User signs up, connects Google Calendar via betterauth

The user can open the meeting's ongoing call tab (§6), which polls bot status and offers highlight + scratchpad once the bot has joined.
When the call ends, MeetingBaas's callback notifies us; the recording and transcript are available as short-lived signed URLs.
The single worker (§7) , generates our own summary/action items (timestamp-linked) and transcript embeddings, and marks the meeting ready based on the transcript.
The meeting appears in the library with player, transcript, summary, action items, highlights, a share link, and (once built) the Q&A chatbot.

5. Bot status mapping

Store MeetingBaas's raw status string (from GET /bots/{id}/status) on the Meeting row, and derive the UI state from it:

UI state	MeetingBaas status values
Starting soon	(our own pre-dispatch state, before create-bot is called)
Joining…	queued, pickup_delayed, joining_call, in_waiting_room, in_waiting_for_host
In call — recording	in_call_recording, recording_resumed, in_call_not_recording
Call ended, processing	call_ended, recording_succeeded, transcribing
Ready	completed
Failed to join	bot_rejected, invalid_meeting_url, meeting_error, waiting_room_timeout, bot_removed_too_early, any MEET_LOGIN_* value
Failed processing	failed, transcription_failed, recording_failed
