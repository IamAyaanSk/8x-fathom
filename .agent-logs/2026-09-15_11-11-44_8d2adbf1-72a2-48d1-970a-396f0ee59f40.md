The state_mismatch error indicates that state verification failed during the OAuth callback. This is a security mechanism to prevent CSRF and replay attacks by ensuring the callback truly belongs to the same browser session that started it.

There are several specific causes for state_mismatch:

1. "Verification not found" (Database strategy)
The most common cause. The state value from the OAuth provider was used to look up a verification record in the database, but none was found.

Common causes:

User took too long (>10 minutes) on the provider's login page — verification records expire and get cleaned up
The callback URL was loaded twice — the verification record is deleted after first successful lookup
Secondary storage (Redis) key evicted without database fallback
Multi-instance deployment without shared database
Secret rotation with hashed identifiers
OAuth provider modified the state parameter
2. "Auth state cookie not found" (Cookie strategy)
The encrypted state cookie wasn't present on the callback request.

Common causes:

Browser blocked the cookie (third-party restrictions, Safari ITP, incognito mode)
Cookie domain/path mismatch
Reverse proxy dropped the Cookie header
User started in one tab, completed in another
3. "Request expired"
The state data was found but its expiresAt timestamp has passed (10-minute validity).

Fixes
Ensure your database is shared across all instances
Use a stable custom domain (avoid .vercel.app preview subdomains)
Verify cookie attributes (SameSite, Secure) match your deployment
If using Redis/secondary storage, set verification.storeInDatabase: true as fallback
Don't rotate BETTER_AUTH_SECRET during active OAuth flows
Run npx auth migrate to ensure the verification table exists
If needed, you can skip the state cookie check (not recommended unless you understand the security implications):


export const auth = betterAuth({
	account: {
		skipStateCookieCheck: true,
	},
});
