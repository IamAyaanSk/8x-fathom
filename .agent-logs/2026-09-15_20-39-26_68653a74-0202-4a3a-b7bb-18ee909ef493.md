Summary generation is wired in the worker as the first processing step.

### Flow
1. **Claim** meetings with `processingStatus = pending`, or `processing` with no summary yet (retry after a crash).
2. **Transaction** — row lock + set `processingStatus` to `processing`.
3. **Per meeting** (outside the transaction):
   - Load transcript from R2 via `transcriptR2Key`
   - Parse MeetingBaas output / raw / flat `utterances` JSON → plain text
   - Call `generateMeetingSummary({ template: 'enhanced', ... })`
   - Persist `meeting.summary`
4. **On error** — log and set `processingStatus` to `failed`.
5. **On success** — stays `processing` (action items / embeddings / `ready` come later).

### New worker modules
- `r2-client.ts` — S3-compatible GET from R2  
- `meeting-transcript.ts` — JSON → `Speaker: line` text  
- `process-meeting-summary.ts` — single-meeting summary step  
- `process-pending-meetings.ts` — batch orchestration
