Implemented **`POST /api/v1/meetings/:meetingId/summary/generate`** end to end.

### API

- **Body:** `{ template: SummaryTemplateId, detail?: string }` — `detail` maps to `additionalDirections` in `generateMeetingSummary` (trimmed, max 4000 chars).
- **Response:** `{ success, message, data: { summary } }`
- **Auth:** session required; meeting must belong to the user.
- **Behavior:** loads transcript from R2, calls `@repo/ai` `generateMeetingSummary`, persists `Meeting.summary`, returns the new text.

### Files

| Layer                                      | Change                                                                                                                                          |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/shared-validations`              | `summaryTemplateIdSchema` (single source for API + AI)                                                                                          |
| `packages/api-contract/src/v1/meetings.ts` | request/response Zod schemas + types                                                                                                            |
| `apps/server`                              | `r2-client`, `load-meeting-transcript`, `meeting-summary` controller, route; `@repo/ai`; LM Studio / Cloudflare env validation (same as worker) |
| `packages/api-client`                      | `postMeetingSummaryGenerate` + `usePostMeetingSummaryGenerateMutation`                                                                          |

### Example

```http
POST /api/v1/meetings/{id}/summary/generate
Content-Type: application/json

{
  "template": "sales_meddpicc",
  "detail": "Emphasize budget and timeline if mentioned."
}
```

**Errors:** `400` invalid body, `404` not found, `409` no transcript yet, `502` load/generation failure.

Ensure the server `.env` includes `LM_STUDIO_BASE_URL` and `LM_STUDIO_API_KEY` in dev (same as the worker) so summary generation can run on the API process.
